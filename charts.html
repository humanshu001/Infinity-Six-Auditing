How to read this page. All numbers below are projected against the actual on-chain reserves above. The death spiral attack is the one described in finding C-1: someone dumps i6 directly into the LP (transfer + sync()), which collapses getSpotPrice(). The next withdraw() call then mints usdtReward × 1e18 / spot i6 to the withdrawer — producing arbitrarily inflated mints when spot is low.

Key observation. The USDT leg of the pool is not drained by the spiral — the 595,319 USDT sits inside the pair throughout, because withdraw() mints fresh i6 from the token contract rather than swapping against the LP. What changes is the i6 leg and the spot it implies, which then governs the size of every subsequent mint. The 595,319 USDT only leaves the pair if someone performs an actual swap (e.g. via invest()'s 60% USDT→i6 swap, which would actually counter the spiral).

7. What changes if C-1 + C-2 are fixed

The recommended fixes are: (i) accept minTokensOut on withdraw(), (ii) read price from a 30-minute TWAP instead of spot, (iii) cap the mint via a DAO-tunable MAX_TOKENS_PER_USD, and (iv) cap totalSupply() at a hard ceiling inside mint().

Same aggressive 30-day scenario with the fixes applied. The TWAP smooths short-term spot manipulation, and the MAX_SUPPLY cap puts a hard ceiling on supply growth. Both curves flatten quickly.
