==========================================================================
41_StressSimulation -- 10,000-user economic stress + death-spiral run
                       (LIVE pool: 756,000 USDT / 600,000 i6 = 1.26 USDT/i6)
==========================================================================

What this suite tests
---------------------
Drive the protocol with a realistic 10k-user load against the LIVE pool
liquidity and watch:
  * pool reserves (USDT + i6)
  * spot price (`getSpotPrice()` reads)
  * i6 totalSupply (mint inflation)
  * USDT pulled out vs USDT deposited

Real liquidity used here
------------------------
  pool i6 reserve     = 600,000 i6
  i6 price            = 1.26 USDT/i6
  pool USDT reserve   = 600,000 * 1.26 = 756,000 USDT

Tree (10,050 total invests)
---------------------------
  layer 0  ORIGIN_HARDCODED (genesis 50,000 USDT seed)
  layer 1  50 sponsors under ORIGIN (uses 50 of ORIGIN's 200 direct slots)
  layer 2  10,000 end users, 200 per L1 sponsor (fills MAX_DIRECTS each)
Each invest = 100 USDT (MIN_INVESTMENT).

How it tests it
---------------
Standalone (no BSC fork) deploy of the REAL InfinitySixToken +
InfinitySixSystem against stateful constant-product mocks:
  * StressMockUSDT   -- OZ ERC20 with public mint
  * StressMockPair   -- real balances, V2-style getReserves(), sync()
  * StressMockRouter -- PancakeSwap V2 math (0.25% fee) for swap +
                        addLiquidity, quote, getAmountsOut
The mocks preserve real constant-product price math, so trajectories
match what would happen on real PancakeSwap under the same trades.

Plain English (WORST)
---------------------
This IS the live pool. With 10k users running through invest then
withdraw+dump, the pool ends 88% drained and the price collapses 150x
(from 1.26 to 0.0084). i6 supply inflates 9x. The contract never
reverted -- nothing capped the mint, nothing protected withdrawers from
the falling price.

  Phase 1 (INVEST):
    The 60% USDT-to-i6 swap on every invest is a buy. Cumulative 600k USDT
    in buys against the 756k seed pumped spot from 1.26 to 3.47 -- a
    2.75x pump just from organic invest activity.

  Phase 2 (WITHDRAW + DUMP):
    Each withdrawer mints i6 against the live spot price and immediately
    sells. As sells push spot down, the next withdrawer mints MORE i6
    (formula `usdtReward * 1e18 / spotPrice` amplifies as denominator
    shrinks), then dumps more. Spot fell from 3.47 -> 0.0084 over the
    10k withdraw run -- 413x collapse during withdraw phase alone.

What this proves about the open audit findings
==========================================================================

C-1 (SpotPriceMint, no `minTokensOut` on withdraw):
  Without a slippage guard, every withdrawer mints against the live spot.
  When earlier dumps crash spot, later withdrawers mint geometrically
  more tokens. On the LIVE pool this took the spot from 1.26 to 0.0084
  in a single 10k-user run.

C-2 (NoMaxSupply on i6 token):
  9.1x supply inflation happened with NO revert, NO cap, NO event. The
  protocol let the mint formula run all the way to 10.97M i6 against a
  150x price collapse.

Renouncing the DAO does NOT touch these paths:
  * `withdraw()` is user-callable, not DAO-gated.
  * `mint()` is `onlySystem`, called automatically inside withdraw.
  * The PancakeSwap pair is public -- any wallet with i6 can move spot.

Both findings must be patched BEFORE renouncing or this trajectory
becomes reachable on mainnet by any combination of 10k withdrawers (or
fewer, with bigger packages).
