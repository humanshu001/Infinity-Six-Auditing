# Economic Attack Audit Results

### 1. Spot Price Oracle Manipulation Vulnerability
* Code location: `getSpotPrice`
* Impact: Relying on spot reserves via UniswapV2Pair's `getReserves()` to calculate the withdrawal exchange rate introduces high vulnerability to price manipulation. An attacker can manipulate pool reserves (e.g. via flash loans or large swaps) to artificially drop the price of the project token, causing the system to mint excessive quantities of the project token during a withdrawal, which are then dumped to drain the liquidity pool.
* Verification: Verified that when reserves are manipulated to reduce the spot price from 1.0 USDT to 0.1 USDT, a withdrawal mints 10x more project tokens (636 tokens vs ~63 tokens normally).

---

### 2. Permanent Booster State Invariant Bypass
* Code location: `_checkAndApplyBooster`
* Impact: Booster rate qualification (`directBoosterCount >= 3` and `directBoosterBusiness >= deposits`) is only evaluated during user registration and direct investments. Once a user receives the boosted status, it is locked permanently (`isBoosted = true`). Even if downline refers withdraw or their investments expire (isActive becomes false), the boost is never revoked.
* Verification: Verified that the sponsor's boosted status remains active and locked permanently after being qualified, irrespective of downstream activity changes.
